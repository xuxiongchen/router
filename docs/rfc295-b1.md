## Four different capabilities

| Name | Evidence / meaning | Writes physical index? |
|---|---|---|
| Product `--policy cache_aware` | Existing approximate request-text affinity | No |
| CL `--kv-load-guard` | Existing one-extra-in-flight slack for physical KV; history also respects it | No |
| `--kv-fallback-policy cache_aware` under `kv_aware` | Downstream-compatible option name for bounded **exact-token history**, then nonblank session | No |
| Physical KV ownership | Real accepted generation-bound Worker events, with existing score semantics | Only event ingestion |

The fallback option does NOT invoke the standalone character tree. Default is
`least_load` (off), with no history store/cleaner. Same option names are wired
through Rust config, native CLI, Python CLI and PyO3 kwargs. Existing
Python/PyO3 positional slots are preserved by appending the new arguments.
Existing `cache_threshold`, `balance_abs_threshold`, `balance_rel_threshold`,
`eviction_interval_secs`, `max_tree_size` configure the separate history store
when opted in. `kv_fallback_history_ttl_secs` defaults to 300 seconds.

Within the existing legal/load-protected candidate set: physical KV selection,
then exact history, then nonblank session, then the existing fair least-load
choice. Hints do not advance the fair tie cursor. Existing native/legacy physical
scores retain their stored-block meaning; only verified automatic Dense mode
reports the reusable-token prediction. History never increases either physical
score, `reusable_prefix_tokens`, or Worker usage/cached-token counters.

## State and boundaries

| State / event | Behavior |
|---|---|
| Selection | One pending reservation per actual attempt, within the existing selection/load critical section |
| Concurrent matching input | Pending hints may colocate; they are never HBM proof |
| Regular successful 2xx headers | Commit history observation, not completed GPU work or completed stream |
| Error/cancel/timeout/drop before headers | Rollback pending; version-specific invalidation of a failed committed source hint |
| Retry | Old attempt drops; same prepared input, new reservation and load lease |
| Body failure or disconnect after commit | Header observation remains advisory until eviction/invalidation; original transport/load cleanup remains |
| Clear, roll, retirement, replacement | Index write fence synchronously purges relevant history; same-generation clear also purges pending |
| Late commit | Bridge contract read fence → index generation read fence → store lock; invalidation wins if first |
| Invalid render contract | No retry/dispatch under old contract; history cannot bypass this. Old unreachable hints expire by TTL |
| Event view unavailable, execution still valid | Purge history/ownership; preserve legacy raw fallback where CL/prepared-input guards permit it; no reservation/physical claim |
| TTL / capacity | Pending and committed associations count toward one logical bound; live pending entries are not capacity-evicted; expired pending cannot commit |
| Shutdown | Cleaner wake/join; reservation weak references cannot keep the store alive |

Capacity unit is one exact-prefix-token association plus one session association
per entry; **not bytes or an RSS guarantee**. Long requests that cannot reserve
do not gain advisory affinity. No Python, network call, or await under index,
history, or selection locks. There is no second load counter or provider.

Identity includes the Router-owned immutable hash/model configuration, process
tokenizer contract, render contract ID/epoch, complete equal token prefixes,
and a conservative namespace partition. Authentication/tenant/unknown headers
and the request `user` field partition hints; common transport/request-ID/trace
headers do not. Raw identity values are not logged. Nonblank session keys are
scoped to that same namespace. Completion and verified Chat may share only
when these scopes and effective tokens agree. Unsupported exact input supplies
no history request; this is not the downstream non-exact Agent advisory path.
Original ingress and existing CT-derived backend-body rules remain unchanged.
Typed ingress derives the same scope through serialization only when history
is enabled; absent, malformed or unserializable scope fails closed for history.
This advisory partition is not a new physical multi-tenant cache-isolation
guarantee.

| `events.epoch/topic/next_sequence`, resolved endpoint | Actual initialized publisher, boot UUID, publish watermark | Stock sequence and configured endpoint do not bind metadata to a publisher incarnation |

Proposed coordination: M1 input/cache scope and target generation; M3/M5 narrow
read-only runtime discovery plus event-incarnation binding; M7 existing load
lease; M8 Regular successful-header observation hook. Reuse the existing
utility-RPC chain, not an arbitrary RPC endpoint. Keep the existing single
[linked Worker proposal](dependencies/vllm-0.29-kv-capabilities.md) separate.
Do not reinstall the old six-patch chain.

Restricted zero-engine-change alternative: retain explicitly configured,
already supported native/static inputs and advisory history under that narrower
deployment contract; or keep standalone RR/cache_aware. Neither is automatic
generic Dense runtime verification, transparent restart recovery, nor #294's
complete EXACT/replay state machine. The proposed field source gap should be
resolved with maintainers, not hidden by deleting checks or renaming a private
endpoint as stock `/server_info`.
